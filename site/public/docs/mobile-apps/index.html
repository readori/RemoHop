移动端应用

仓库里有两个移动端应用：mobile/android（Android）和 mobile/ios（iOS）。它们都是控制端：一个原生外壳加一个 WebView，WebView 显示进程内运行的 remohop web 网关（Go 核心通过 gomobile 绑定）。

  • 只是控制端。把 Android 或 iOS 设备作为被控机没有实现。
  • iOS 应用可以从 App Store 安装。Android 应用已提交 Google Play 审核，审核通过之前需要自己构建。
  • Android：运行 mobile/android/build.sh（需要 Go、JDK 17+、Android SDK 和 NDK，ANDROID_HOME 要设置），默认生成 debug APK 并运行 JVM 单元测试。
  • iOS：在 macOS 上先运行 mobile/ios/build-xcframework.sh 生成 Remohopcore.xcframework，再用 Xcode 构建 mobile/ios/RemoHop.xcodeproj。
  • 每次改动都在 CI 中测试：iOS 应用在 iOS 模拟器中运行，应用内的测试用地址和密码连接一台 remohop host，在终端里执行一条命令，并在“文件”里列出一个目录；Android 应用在模拟器上运行，插桩测试与一台真实的被控端配对，使用终端、文件、下载、剪贴板和桌面标签页，并检查设置页在旋转、重建以及从桌面图标重新打开后保持不变。如果你在自己的设备上遇到问题，请告诉我们。
  • 切到后台再回来：iOS 会收回被挂起应用的监听套接字。因此 iOS 应用进入后台时会关闭应用内网关的监听，回到前台时在同一端口重新打开；两个应用每次回到前台时也会检查网关是否有响应，没有响应就重新打开监听。网关持有的被控端会话不受影响。如果页面仍然收不到响应，会请应用再检查一次并重试；仍然失败时显示“网关没有响应”和“重试”按钮。
  • 会话在你断开之前一直保持连接。如果连接中断（应用被挂起、手机切换了网络、短暂断网），应用会自动重新连接，期间显示“正在重新连接…”，连上后恢复原来打开的标签页：终端会重新接入被控端上的同一个 shell。要求主人批准每次登录的被控端会再次请求批准；被拒绝时会话结束并说明原因。Android 上应用在后台时由一条通知（“已连接到 …”，带“断开连接”）保持会话；iOS 上短暂切到别的应用不会断开，离开较久则在回来时自动重连。应用如何重新登录见 security.md。
  • 纯 IPv6 网络：iOS 应用通过网络的 NAT64 访问 IPv4 地址（按 IP:端口 输入的被控端、按地址填写的汇合服务器），见工作原理。
  • 如果填写的汇合服务器地址其实是一台 RemoHop 被控端，会明确报告（错误码 signal_is_host）：请直接用这个地址连接被控端。
  • 移动端应用目前不支持账号登录。
  • 界面语言：原生界面和网页部分都有简体中文和英文。默认跟随系统（系统语言是任何一种中文时显示中文，否则显示英文）；在“设置 > 语言”里切换，立即生效，已建立的会话不会断开。Android 13 及以上版本中，系统的“应用语言”设置与此是同一个选项。
