Quick start

This page covers the five steps from nothing to a first connection. For the full syntax of a command, run remohop help <command>. Everything else is in the documentation, one page per topic, listed below.

The walkthrough assumes three machines: a small server with a public address for the rendezvous server (sig.example.net below), the host you want to control, and your own workstation. On a LAN you can skip the server.

1. Install

On every machine, install remohop with the install script (Windows: install.ps1), a package or an archive from the download page:

curl -fsSLO https://github.com/readori/RemoHop/releases/latest/download/install.sh
sh install.sh

It puts remohop in ~/.local/bin (as root: /usr/local/bin). To build it yourself instead, see Building from source.

2. Run a rendezvous server

On a machine with a public IP, open UDP ports 21116 and 21117, then run:

remohop signal

The server prints its public key on start. Clients can pin it with remohop config set signal-pin KEY. To relay sessions that cannot connect directly, start it with remohop signal --relay instead. For a long-running server, see Self-hosting.

3. Start the host

remohop config set signal sig.example.net
remohop host

remohop host runs in the foreground and prints the ID and the temporary password. To start at boot, install it as a service:

remohop service install
remohop status --show-password

This writes a systemd unit (Linux), a launchd job (macOS) or a Windows service. The service has its own identity, ID and password; it is not the same instance as an remohop host you start by hand. A system-wide service and the Windows service cannot see the desktop session, so use the per-user service when you need screenshots or remote desktop. On Windows, remohop service install --unattended instead gives the service's clients the console session, including the sign-in screen, the lock screen and UAC prompts (off by default); the desktop app's unattended access installs it this way.

For a fixed password run remohop passwd. It asks without echo and never prints the password again.

4. Connect and pair

remohop config set signal sig.example.net
remohop 276941009 ping
remohop 276941009 pair --name dev
remohop dev info
  • ping shows the path to the host. The first connection needs the password, so it prompts.
  • pair --name dev asks for the password once, then stores a pairing token bound to this machine's identity and saves the alias dev.
  • After that, remohop dev ... needs no password. remohop devices lists saved hosts and whether they are online.

5. Use it

remohop dev shell                       # persistent terminal; press Enter then ~. to detach
remohop dev cp ./build.tar.gz :/tmp/    # remote paths start with a colon
remohop dev forward -b 18080:8080       # remote port 8080 on local port 18080
remohop dev desktop                     # view and control the remote screen in a browser
remohop web --target dev                # browser client: desktop, terminal, files, clipboard

Without a server: LAN or public IP

If you can reach the host by address, you need no rendezvous server. On the host:

remohop host --no-signal --listen :21118

On the client, use the address in place of the ID. A password is still required:

remohop 192.168.1.5:21118 pair --name lab
remohop lab info

For AI agents

Pair first, then add the MCP server to the agent's host program. With Claude Code:

claude mcp add remohop -- remohop mcp --target 276941009

For clients that read an mcpServers configuration, such as Cursor:

{
  "mcpServers": {
    "remohop": { "command": "remohop", "args": ["mcp"] }
  }
}

An agent acts on the remote machine with the privileges of the user who runs the host. Pair only the machines you want an agent to reach, switch off features it does not need (for example remohop config feature input off), and revoke the pairing with remohop host revoke when you are done.

Full documentation

The user guide has one page per topic, the same in English and Chinese; the in-depth references are in English. When something fails, start with troubleshooting.

Every remote command has the form remohop <ID> <command>. The pages use dev as the example alias, from remohop <ID> pair --name dev. Run remohop help <command> for the full syntax.
