支持与联系

RemoHop 是独立的开源项目。有问题可以写信，也可以在 Telegram 上找我们：

support@remohop.com Telegram：@remohop

中文或英文都可以。安全问题和需要附带日志的报告请用邮件。这是一个小团队维护的项目，没有承诺的响应时间。

先自己查一下

  • 故障排查文档（英文）按错误信息逐条解释：连不上、密码被拒、没有直连路径、挂载、VPN、远程桌面黑屏、ffmpeg 和编码器。
  • remohop <ID> ping 会显示当前路径是 lan、direct、punched 还是 relayed，多数连接问题从这里就能看出原因。
  • 在任何命令前加 -v（或设置 REMOHOP_DEBUG=1）可以在 stderr 上看到调试日志。
  • 功能与限制一页的“状态与限制”列出了已知没有测试过的平台和功能。

报告问题时请附上

  1. 客户端上 remohop -v <出问题的命令> 的输出。
  2. 被控机上 remohop status、remohop log 和 remohop config 的输出。
  3. remohop version，或者你编译时所用的提交。
  4. 两端的操作系统和版本；移动应用请写明机型和系统版本。
  5. 两端的网络情况：家用宽带、公司网络、移动网络，是否经过代理，用的是谁的汇合服务器。
  6. 你预期发生什么，实际发生了什么。

发送前请删掉机密。不要把密码、配对令牌、identity.key 的内容、网关地址里的令牌或 Cloudflare Access 的密钥发给我们。ID 和公网 IP 地址如果不想透露，也可以打码。

安全问题

发现安全漏洞时，请不要在公开的 issue 或论坛里披露，直接发邮件到 support@remohop.com，标题里带上“security”。请写明受影响的版本或提交、复现步骤和你判断的影响。我们会回信确认收到，并在修复后与你商量公开的时间。安全模型见安全一页。

其他事项

商业授权
写信到 info@remohop.com，说明用途。见许可证。
隐私与数据删除
见隐私政策。应用和软件不向我们回传数据；要删除 RemoHop 服务器上的账号，执行 remohop account delete --yes，或写信给我们。
滥用举报
如果有人通过 RemoHop 运营的服务器滥用服务，请把时间（含时区）、相关的 IP 地址或 ID 发给我们。
贡献代码
见仓库里的 CONTRIBUTING.md。合并之前需要签署贡献者许可协议。
