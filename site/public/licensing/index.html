许可证

RemoHop 采用双许可：一份开源许可证，一份商业授权。具有法律效力的是许可证原文，这一页只是帮助阅读的说明。

开源：GNU AGPL-3.0

所有人都可以按 GNU Affero General Public License 第 3 版（AGPL-3.0-only）使用、研究、修改和再分发 RemoHop。全文见仓库里的 LICENSE。

  • 你可以出于任何目的运行 RemoHop，包括商用。
  • 如果你分发 RemoHop，无论是否修改过，都必须按 AGPL-3.0 提供对应的源代码。
  • 通过网络提供也算。如果你修改了 RemoHop 并让别人通过网络使用它，例如为他人运行修改过的 remohop signal 汇合服务器或 remohop web 网关，就必须向这些用户提供修改后版本的源代码（AGPL-3.0 第 13 条）。
  • 运行未修改的 RemoHop，或者只是自己使用，除许可证要求的声明之外没有额外义务。

商业授权

AGPL-3.0 不适合你的用途时，可以向版权方 RemoHop 项目购买商业授权。常见的情况：

  • 把 RemoHop 放进闭源产品里一起发布；
  • 为他人运行修改过的服务器，但不想公开修改；
  • 通过条款与 AGPL 冲突的应用商店分发。

商业授权请联系：info@remohop.com。信里请说明你打算怎么用 RemoHop（嵌入产品、托管服务还是内部分发）和大致规模。

贡献代码

因为 RemoHop 同时以商业授权提供，贡献的代码必须由一份签署过的贡献者许可协议（CLA）覆盖，使版权方可以按两种许可证分发它。你保留自己作品的版权。详见仓库里的 CONTRIBUTING.md；关于 CLA 的问题可以写信到 info@remohop.com。

第三方软件

RemoHop 链接的 Go 模块采用 MIT、BSD-2-Clause、BSD-3-Clause、ISC 和 Apache-2.0 许可证，都与 AGPL-3.0 兼容。发布的压缩包里会附带它们的许可证全文（THIRD_PARTY_LICENSES.txt）。

RemoHop 不包含也不分发 ffmpeg。远程桌面调用的是被控机上已经安装的 ffmpeg，它作为独立的程序运行。把某个 ffmpeg 构建和 RemoHop 捆绑在一起的人，需要自行承担那个构建的许可证条款：带 libx264 的 ffmpeg 采用 GPL。

Windows 上的 VPN 客户端需要 Wintun 驱动，remohop 不包含也不下载它。

二次开发必须署名

依据 AGPL-3.0 第 7 条，RemoHop 附加了以下条款，适用于所有基于 RemoHop 的作品（分支、修改版，或包含 RemoHop 代码的产品）：

  1. 标明项目名称和开源地址。例如：“基于 RemoHop（https://github.com/readori/RemoHop），© RemoHop 项目，按 AGPL-3.0 授权。”源代码里要保留 NOTICE 文件并写进 README；作品展示法律声明的地方（“关于”或“设置”页面、version 或 help 命令的输出、网页界面的页脚）也要写明。不得删除已有的版权和署名声明。
  2. 修改版要标明已修改。不得自称是原版 RemoHop，也不得暗示由 RemoHop 项目制作或认可。
  3. 名称和标志另行保留。AGPL-3.0 不授予把“RemoHop”名称或标志用作其他产品名称或品牌的权利（上面要求的署名除外），请为你的作品另取名字。

完整条款见 LICENSING.md。通过商业授权获得的软件不适用这些条款。
