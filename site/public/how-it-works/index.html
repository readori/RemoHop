工作原理：P2P 打洞与端到端加密

RemoHop 怎样把两台设备直接连起来：汇合服务器负责什么、四种连接路径、默认端口、连接建立的六个步骤，以及会话为什么只有两端能读。更细的说明见文档《工作原理》和安全模型。

概述：被控端和控制端先联系 RemoHop 汇合服务器（remohop signal），完成 ID 注册、在线状态、NAT 类型探测和候选地址交换；随后双方同时互发 UDP 探测包打洞，在第一条有应答的路径上建立 QUIC 直连，用 TLS 1.3 + CPace 密码认证（绑定 Ed25519 身份密钥）做端到端加密。远程桌面、终端、文件等全部功能都在这一条会话里多路传输；打洞失败约 1.5 秒内自动切到（可选的）中继，中继也只转发密文。

连接示意图

RemoHop 汇合服务器 remohop signal

会话里传输的数据（不经服务器）

  • 远程桌面视频 H.264 / AV1，最高 4K 60 帧
  • 键盘、鼠标（连发、组合键）
  • 音频 Opus
  • 终端与后台任务
  • 文件（断点续传）
  • 剪贴板双向同步
  • 端口转发 / VPN / 虚拟组网
  • 串口、USB、屏幕截图

特殊网络与可选项

  • 按地址直连：输入 地址:端口，完全不用服务器
  • Tailscale：双方在同一 tailnet 时优先走它
  • NAT64：纯 IPv6 网络（如 iOS 审核网络）
  • 拒绝中继：remohop config relay off

稳定性

  • 短暂断网不掉线，会话断开自动重连
  • 被控端换网、地址变化：几秒内重新登记
  • 小 MTU 网络（1200 字节起步）也能连
  • 对方意外离线约 25 秒内发现

四种连接路径（自动选择，最快的胜出）

  1. ① 局域网直连 lan

    同一网络里直接连，数据不出局域网

    建立约几毫秒

  2. ② 公网打洞 punched

    跨网络、锥形 NAT，P2P 直连

    建立约 30–60 ms

  3. ③ 中继 relayed（可选）

    对称 NAT、客户端隔离时；只转发密文

    约 1.5 秒内切换

  4. ④ WebSocket 桥（可选）

    只能访问网页（HTTPS 443）的网络

    记住后几十毫秒

主要协议与技术

  • UDP 打洞（低 TTL 预热、同时发探测）+ QUIC
  • TLS 1.3 加密，CPace 密码认证绑定 TLS 与双方身份
  • 配对令牌：配对后免密码，可随时撤销
  • 授权范围（只看 / 控制 / 文件 / 命令白名单）+ 审计日志
  • 硬件编码 NVENC / QSV / AMF / VideoToolbox / VAAPI

连接建立流程（时序）

  1. 注册：被控端用 Ed25519 身份向汇合服务器注册，拿到 9 位 ID 并保持心跳。
  2. 发起：控制端输入 ID（或直接输入 地址:端口，无需服务器）。
  3. 交换：服务器下发双方候选地址（局域网 / 公网 / IPv6 / Tailscale）与 NAT 类型。
  4. 打洞：双方同时互发探测包，第一条应答的路径胜出（局域网优先）；1.5 秒无路径则并行走中继。
  5. 认证：在 QUIC（TLS 1.3）上跑 CPace，密码或配对令牌从不上网传输；可弹窗批准。
  6. 会话：桌面、终端、文件等在同一条加密会话里多路传输，断线自动重连。

NAT 打洞（UDP Hole Punching）原理

打洞前
设备 A NAT✕NAT 设备 B
打洞后
设备 A ⟵ QUIC 直连 · 端到端加密 ⟶ 设备 B
  • 双方先向汇合服务器登记，服务器看到各自的公网地址和端口。
  • 服务器把对方的候选地址告诉双方，双方同时向对方发 UDP 探测。
  • 出站的探测在各自 NAT 上“开洞”，对方的包就能进来。
  • 锥形 NAT 基本都能打通；双方都是对称型 NAT 时自动走中继。

关键结论

  • 汇合服务器只负责注册、在线、打洞协调（和可选中继），从不接触明文。
  • 打洞成功后数据在两台设备之间直接传输，端到端加密。
  • 不需要注册账号；也能完全不用服务器，按地址直连。
  • 一个程序：控制、被控、服务器、网页、AI 接口全包含，可自建。
  • 体验主要取决于 NAT 类型与网络质量；连不通 1.5 秒内转中继。
