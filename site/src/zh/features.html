一次会话的样子

适合谁用

适合

  • 要管理自己的几台机器：家里的主机、办公室的工作站、NAT 后面的开发板，用桌面应用、浏览器、手机或命令行都行。
  • 要远程帮家人朋友看电脑：对方双击“快速协助”，念出 ID 和密码，点“允许”就行。
  • 想让 AI 代理（Claude Code、Cursor 等）在另一台机器上执行命令、读写文件、看屏幕。
  • 不想把会话内容交给第三方服务器，愿意自己运行一台很小的汇合服务器。
  • 需要的不只是屏幕：还要端口转发、挂载目录、串口、剪贴板或一条 VPN 链路。

目前不适合

  • 需要经过代码签名的 Windows 程序。Windows 版还没有代码签名，SmartScreen 会提示（macOS 版已签名并经过公证）。
  • 要控制 iPhone 或 iPad。iOS 不允许任何应用控制设备，iPhone 和 iPad 只能共享屏幕给别人看（Android 手机可以被控制）。
  • 需要经过第三方审计的产品。RemoHop 还没有做过独立审计。
  • 被控机用的是原生 Wayland 桌面。屏幕采集目前只支持 X11、macOS 和 Windows。

常做的事，对应的命令

远程命令的格式都是 remohop <ID> <命令>。下面用别名 dev 代替 ID，它来自 remohop 276941009 pair --name dev：配对时输入一次密码，之后不再需要。

终端和后台任务

交互式 shell 是持久的：断开后会话还在被控机上运行，默认保留 30 分钟，重连时回放你错过的输出。被控机是 Windows 时，shell 是 PowerShell。

remohop dev shell
remohop dev shell -c 'make test' --cwd src/app --timeout 10m
remohop dev spawn --name build make -j8
remohop dev logs -f build

文件

远程路径以 : 开头。8 MiB 及以上的文件中断后，重新执行同一条命令会接着传。挂载在 Linux 上用 FUSE，在 macOS 和 Windows 上用系统自带的 WebDAV 客户端。

remohop dev cp ./build.tar.gz :/tmp/
remohop dev cp -rp :project .
remohop dev sync -n --delete --exclude node_modules ./site :/var/www/site
remohop dev mount :~/src/app ~/mnt/app

端口转发和 VPN

转发相当于 ssh -L 和 ssh -R，也能转发 UDP。VPN 在会话里建立一条 IPv4 链路（本机 10.77.0.2，被控机 10.77.0.1）。两端都是 Linux 是测试过的组合；macOS 客户端和 Windows 的 Wintun 网卡都只在托管 CI 机器上验证过，还没在真实网络里长期用过。

remohop dev forward -b 18080:8080
remohop dev forward -b --udp 5353:53
remohop dev forward -R 9000:3000
sudo remohop dev vpn up --route 192.168.1.0/24 -b

屏幕和远程桌面

desktop 在本机浏览器里打开查看器，用 H.264 或 AV1 传输，可以录制成 MP4。被控机需要装有带编码器的 ffmpeg。在一台只有 CPU 的 4 核虚拟机上实测，H.264 的端到端延迟约 20 ms（720p）和 31 ms（1080p）。查看器可以选画质（原始分辨率或最高 2160p 到 480p）、帧率（30 到 144 fps，“自动”按显示器刷新率，最高 120）和显示器，“统计”按钮显示码率、延迟和近 10 秒的丢帧数。

remohop dev desktop --max-height 1080 --fps 30
remohop dev desktop --codec h264 --record meeting.mp4
remohop dev screenshot -o /tmp/screen.png
remohop dev click 412 230

剪贴板

双向同步文本和图片。经过的内容会记进本机的历史，可以按编号取回或重新发送。

remohop dev clip sync
remohop dev clip get -o shot.png
remohop clip history -n 5
remohop dev clip history send 2

串口和 USB

把远程机器的串口变成本机的虚拟串口，任何终端程序都能打开（本机需要是 Linux 或 macOS）。USB/IP 要求两端都是 Linux 且有 root 权限，目前只在模拟环境里测试过。

remohop dev serial -b ttyUSB0 115200 --local /tmp/board
picocom /tmp/board
sudo remohop dev usb attach -b 1-2

AI 代理

remohop mcp 是一个 stdio 方式的 MCP 服务器，提供 28 个工具（执行命令、读写文件、转发端口、截图、点击和输入）。它只使用你事先保存的配对，不接受密码参数。仓库里另有六个 Agent Skills。另有六个 Agent Skills，会随源码一起公开。

claude mcp add remohop -- remohop mcp
claude mcp add remohop -- remohop mcp --target 276941009

被控端说了算

被控机的主人可以逐项关掉功能、要求每次登录都在本机确认、改用一次性密码，并查看审计日志。改动立即生效，对已经连上的会话也一样。

remohop config feature input off
remohop config ask on
remohop config otp on
remohop log

在浏览器里用：remohop web

remohop web 在本机启动一个浏览器客户端，里面有远程桌面、终端、文件、剪贴板和系统信息。默认只监听 127.0.0.1，地址里带一个猜不到的令牌。Android 和 iOS 应用就是把这个网关放进了应用进程里，见移动应用。

浏览器没法自己打洞，也不会说 RemoHop 的 QUIC 会话，所以 remohop web 这个进程才是真正的客户端：屏幕、按键、文件和你在页面里输入的主机密码，它都看得到。只使用你自己控制的网关。

连接是怎么建立的

  1. 被控机向汇合服务器注册，得到自己的 9 位 ID。
  2. 客户端向汇合服务器查询这个 ID，服务器把双方的候选地址互相告知。
  3. 双方向对方的候选地址发探测包，在各自的 NAT 上打洞，客户端在第一条有应答的路径上建立 QUIC 连接。
  4. 两端在这条连接上用密码做认证密钥交换（CPace）。中间人，包括汇合服务器，没法完成这一步。

对称型 NAT 给每个目的地分配新端口，原本最难打通。现在被控端会请路由器转发它的 UDP 端口（PCP、NAT-PMP 或 UPnP），路由器同意时，对方在哪种 NAT 后面都能直连；按顺序分配端口的对称型 NAT，另一边会探测预测出的端口。都不行时，如果服务器的运营者开启了中继（remohop signal --relay，默认关闭），会话改走中继；中继转发的仍是同一条加密会话，只是更慢，并且有带宽上限（每个会话默认 8 Mbit/s）。走中继期间客户端会在后台继续打洞，打通后会话经 QUIC 连接迁移换到直连，不中断，也不用重新登录。remohop dev ping 会告诉你当前走的是 lan、direct、punched 还是 relayed。没有中继可用时，连接会在大约一秒内失败并给出诊断信息。

各条路径的尝试顺序、端口、六步连接流程和打洞前后的对比见工作原理。

只放行 HTTPS 的网络（CI 运行器、企业网络）可以走服务器的 websocket 桥。经过桥没法打洞，所以这类会话一定走中继，内容照样是密文。能直接访问被控机时可以完全不用服务器：remohop host --no-signal --listen :21118，然后用地址代替 ID。

安全，用大白话说

  • 内容只有两端能读。会话跑在 QUIC 里，内层是 TLS 1.3。汇合服务器和中继看到的都是密文。
  • 密码不上线。登录用的是 CPace 密钥交换，并且和这一条连接绑定。密码本身从不发送，截获了一次失败的登录也没法离线猜密码。
  • 在线猜密码有限速。同一个来源连错三次起锁定 10 秒，之后每次翻倍，最长 10 分钟。临时密码是 8 个随机字符，约 40 比特。
  • 主机密钥首次登录时固定。之后主机换了密钥，客户端会在发送任何登录信息之前拒绝连接。
  • 配对代替密码。配对后客户端保存一个绑定到本机身份的 256 位随机令牌，被控机随时可以用 remohop host revoke 撤销。

也要说清楚它不保护什么：登录成功的客户端，在被控端允许的功能范围内，能做运行 remohop host 的那个用户能做的一切，功能开关以下没有更细的权限模型。汇合服务器看得到元数据：哪些 ID 在线、它们的公网地址、什么时候互相连接。安全模型一页有完整说明。

安装

全部下载都在下载页上：安装脚本，Linux、macOS 和 Windows 的压缩包，.deb/.rpm/.apk 软件包，以及快速协助程序，都列在带签名的 SHA256SUMS 里。在 Linux 和 macOS 上：

curl -fsSLO https://github.com/readori/RemoHop/releases/latest/download/install.sh
sh install.sh

得到的是一个静态链接的程序，已经在 PATH 里。macOS 的下载已签名并经过公证，Windows 的下载尚未做代码签名。也可以从源码编译，见从源码编译。

首个发布版本正在准备中，下载页列出了它会包含的文件。在此之前，需要用 go.mod 里指定的 Go 版本（1.26）从源码编译。得到的是一个静态链接的程序，放进每台机器的 PATH 即可。

git clone {{REPO}}
cd RemoHop
make build        # 生成 bin/remohop（CGO_ENABLED=0）
make cross        # 可选：linux、macOS、Windows 各架构，输出到 dist/

推送 v* 标签时触发的发布工作流会构建 Linux、macOS 和 Windows 的压缩包、.deb/.rpm/.apk 软件包和快速协助程序，并给 SHA256SUMS 签名。macOS 的文件用 Developer ID 签名并经过公证；Windows 的文件尚未做代码签名。

目前没有可下载的发布版本，程序也还没有做代码签名。各平台应用上架后，这一节会换成下载链接，源码也会在那时以 AGPL-3.0 公开。得到的会是一个静态链接的程序，放进每台机器的 PATH 即可。在此之前有问题，请写信到 {{EMAIL}}。

状态与限制

  • Windows 程序没有代码签名。命令行程序没有内置默认服务器（桌面应用和快速协助首次启动时可以选官方服务器）。
  • 没有经过独立的安全审计。
  • NAT 穿透测试用的是 Linux 网络命名空间。真实的家用路由器和 IPv6 路径没有测试过。两个对称型 NAT，或随机分配端口的对称型 NAT 对上端口受限型 NAT，打不通，除非路由器映射了端口或有中继可用。
  • 实体 Mac 上的一切、除一台 macOS 虚拟机里的 VideoToolbox 以外的 GPU 编码器、4K 60 fps，都没有测试过。
  • 串口用伪终端和 picocom 验证过，没有用过真实的 UART。USB/IP 在托管运行器的真实内核上验证过，没有用过实体 USB 设备。
  • 被控端重启后，shell 会话不会保留。
  • 手机作为被控端：真机上的屏幕采集和控制尚未测试；iPhone 和 iPad 只能被观看。
