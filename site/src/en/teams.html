RemoHop Teams: your team decides which machines AI agents may reach, and what they may do there

Teams run more and more agents, and those agents run commands on build machines, test machines and even production servers. Teams gives every agent and every person the same rules: only the machines named, only the features named, deletes, pushes and deploys wait for an admin's approval, and every step leaves a signed audit record and a recording. It runs on your own servers, and the rules are a log signed by your admins' keys, which the server can store but cannot forge.

Who may reach what, in one place

People and their devices go into groups. A policy says which group of people may reach which group of devices, with which features, and which actions need approval. On each host the rule becomes a grant, which that host enforces like any other grant.

What Teams adds

Agents under the same rules

AI agents are covered by the same policies, approvals and audit as people. They count as devices, not users.

People, devices and groups

A team of people and their devices, groups of people and groups of devices, and a policy that connects them. Changes reach the hosts as new grants.

Admin console and CLI

The console runs on the admin's own machine and talks to the team server. There is an admin command line too, for scripts and terminals.

Single sign-on and provisioning

People sign in with OIDC or SAML 2.0 to enrol a device. SCIM 2.0 provisioning brings the people in from your identity provider.

Approvals by admins

When a rule says an action needs approval, a team admin can answer it in the console or the CLI, as well as the host's owner. Each decision is signed with the admin's key, and the host checks the signature.

Central audit and recordings

Hosts sign their audit records into a hash chain and ship them, with session recordings, to the team server. How long they are kept is set on the server.

A log the server cannot forge

Membership and policy are an append-only log of entries signed by admin keys. Hosts verify it themselves; checkpoints and join codes let a new host start from a signed snapshot.

Inside your rendezvous server

The team server runs inside your own remohop signal, so there is nothing else to host. It can meter relay traffic per team.

The log is the root of trust

The team server is useful but not trusted. Every change to who may do what is an entry in the team log, signed by an admin key the log allows to make it. The server keeps the log and passes it on; hosts check every entry before they act on it.

Plain facts

What you get

  • Software you run yourself, on your own servers.
  • An offline license file with an end date. Your server never calls us to check it.
  • Email support with a Teams license.
  • The open-source RemoHop underneath: the same encryption, grants and host-side checks.

What it is not

  • There is no hosted version. Teams runs only on your servers.
  • Support is by email, not around the clock.
  • RemoHop has had no independent security audit. Enterprise customers get help with their own security review.
  • The Teams code is not public, so this page describes it instead of linking to it.
