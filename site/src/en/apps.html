Android and iOS controller apps

The mobile apps let you connect to and operate your computers from a phone or tablet. They are controllers only: a phone cannot be controlled.

Release status: the iOS app is being prepared for TestFlight and is not on the App Store. The Android app is not in any store and there is no APK to download. For now the only way to use either is to build it from source. When they are released, this page will link to the stores.

What is in the app

Both apps have the same structure: a native shell around a WebView that shows the remohop web gateway. The gateway and the Go core run inside the app process and listen only on the phone's own 127.0.0.1. The session is therefore still an end-to-end encrypted peer-to-peer connection between the phone and the host, with no Readori server in between.

  • Remote desktop: view and control the computer's screen, with full screen, quality presets and a monitor switch.
  • Terminal: persistent shell sessions, with helper keys for Esc, Tab, Ctrl and the arrows.
  • Files: browse, upload, download, create folders, rename and delete.
  • Clipboard: move text between the phone and the computer.
  • System information and screenshots.
  • Languages: the app and its pages are in English and Simplified Chinese. They follow the system by default; choose the language in Settings.
  • Settings (native): the language, the rendezvous server's address and key, whether relaying is allowed, the device name, this device's identity fingerprint, pairing by password, and saved hosts.

Current limits

  • Controller only. Using an Android or iOS device as a host is not implemented.
  • No built-in server. Enter your own rendezvous server in the settings, or connect by host:port.
  • No account login.
  • The iOS app has run only in a CI iOS simulator, where an in-app test connects to an remohop host by address and password, runs a command in the terminal and lists a directory in Files. It has not been verified on a physical iPhone or iPad.
  • The Android app has had no real-device test.

The app and your data

The app talks to two kinds of peers only: the hosts you connect to, and the rendezvous server you enter in the settings. The identity key, pairing tokens and settings stay in the app's private directory and are excluded from system backups. The app contains no analytics, advertising or crash-reporting SDK. The privacy policy has the details.

Build it yourself

Android

Needs Go, JDK 17 or later, the Android SDK and NDK, and ANDROID_HOME. By default this produces a debug APK and runs the JVM unit tests:

mobile/android/build.sh

iOS

On macOS, build the Go core as an xcframework first, then build the project with Xcode:

mobile/ios/build-xcframework.sh
open mobile/ios/RemoHop.xcodeproj

First use

  1. On the computer, run remohop host and note the ID (or address) and the password.
  2. In the app's settings, enter your rendezvous server. On the same LAN as the computer you can leave it empty and use an address such as 192.168.1.5:21118 (start the computer with remohop host --no-signal --listen :21118).
  3. On the connect screen, enter the ID or address and the password. Tick the pairing box and you will not need the password next time.

If something goes wrong, see Support. Reports from real devices are especially useful to us.
