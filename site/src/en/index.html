Peer to peer

The server only introduces them; the picture goes straight between the two computers

The rendezvous server finds the other computer by its ID. After that the screen, keyboard, mouse and files go over a direct QUIC connection, end-to-end encrypted with TLS 1.3, and the password never crosses the network. Only when no direct path exists does a relay forward the traffic, and it cannot read it either.

  1. 1. IntroduceBoth sides reach the rendezvous server, find each other by the 9-digit ID and swap addresses.
  2. 2. Punch throughBoth send packets to each other at once, which gets through most home and office routers; the host also asks its router to map a port, and symmetric NATs have their next ports predicted. On a LAN they use the local network.
  3. 3. ConnectOnce the encrypted QUIC channel is up, the server is out of the picture. Without a path a relay takes over in about 1.5 s, and the session moves to a direct path, without a break, as soon as one works.

How it works, in one picture

Sharper, faster, safer

The host decides

Every connection asks first, with a scam warning for new devices. An allowed device only sees the screen until you tick control or files, and you can take either back or disconnect at any time.

2K and 4K quality

Intel, NVIDIA and AMD encoders take frames straight from the GPU, monitors are captured at physical pixels so text stays sharp, and the bitrate follows the network. Native size and a monitor switch are a click away.

Low latency

About 60 ms at 2K and 114 ms at 4K, measured on a LAN. Key-frame requests switch encoders without a gap; the lock screen and UAC pause the picture instead of ending the session.

Up to 144 fps

Pick 30 to 144 fps, or Auto, which follows the display's refresh rate (up to 120). The Stats overlay shows resolution, bitrate, latency and the frames dropped in the last 10 seconds.

Gets through networks

Hole punching, router port mapping (PCP, NAT-PMP, UPnP), port prediction for symmetric NATs, IPv6 and NAT64, and WebSocket when UDP is blocked. A relayed session moves to a direct path once one works.

Phones can be hosts

An Android phone can be viewed and, if you allow it, controlled; an iPhone or iPad can share its screen, view only. A device you allowed may come back without asking for as long as you choose.

Sessions that come back

A new network or a wake from sleep reconnects by itself. In the phone apps a session lasts until you end it, even after the system closed the app, and the terminal returns to the same shell.

More than a desktop

Terminal, resumable file transfer, clipboard, port forwarding, a virtual network and Wake-on-LAN, and AI agents (MCP) can work within the limits you grant.

Yours to run

Use the official rendezvous server signal.remohop.com or run your own with one command on the smallest VM. On a LAN, connect by address with no server at all.

Quick support

Help someone with their computer

They download Quick Support, which needs no installation, and double-click it. The window shows a 9-digit ID and a temporary password in large type, which they read out to you. When you connect, they see your device name, key and address, and you only get in once they click "Allow"; no answer within 60 seconds refuses the request.

By default you can see the screen, use the mouse and keyboard and move files; running commands and reaching their network need an extra tick. Closing the window stops the sharing.

You connect with the desktop app, the browser client, a mobile app or the command line; both sides use the same rendezvous server.

About quick support

Desktop app / command line

Reach your own machines

On the machine to control, open the RemoHop desktop app and allow connections, or run remohop host. Pair once and later connections need no password; unattended access is there too.

# the host
$ remohop host
# your machine
$ remohop 276941009 pair --name dev
$ remohop dev shell
$ remohop web --target dev

On one LAN you can skip the server: run remohop host --no-signal --listen :21118 on the host and use its address instead of the ID.
